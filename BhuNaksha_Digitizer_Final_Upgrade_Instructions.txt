BHUNAKSHA DIGITIZER — PROJECT-SPECIFIC UPGRADE INSTRUCTIONS

Upgrade the existing BhuNaksha/Cadastral Digitizer without removing or breaking any existing functionality.

1. MAIN BUTTONS — EXACTLY THREE

The main workspace must have exactly three primary buttons:

IMPORT ▾ | EXPORT ▾ | SAVE PROJECT

Import ▾:
When clicked, open a dropdown containing:
- Import Project JSON
- Import KMZ/KML
- Import DXF
- Import CSV Vertices
- Import Image
- Import PDF
- Other currently supported formats

Export ▾:
When clicked, open a dropdown containing:
- Export Project JSON
- Export KML
- Export KMZ
- Export DXF
- Export CSV Vertices
- Other currently supported formats
- Existing area/report exports where applicable

Project Import and Project Export must NOT have separate permanent buttons. They must remain inside the Import and Export dropdowns.

Save Project remains a separate main button and should directly save the current editable cadastral project as JSON.

2. AUTOMATIC CADASTRAL OVERLAY

When DXF, CSV, KML/KMZ or Project JSON is imported:
- Automatically create the appropriate layer/geometry.
- Automatically overlay it on the current map.
- Preserve plot numbers and available cadastral attributes.
- Preserve CRS and coordinate precision.
- Do not force the user to manually position imported geometry.
- If CRS cannot reliably be determined, ask the user instead of silently guessing.

3. MOVE/SHIFT CADASTRAL GEOMETRY

Add Move/Shift Geometry inside the existing Edit workflow.

It must work for both imported and digitized cadastral geometry.

Main use case:
Correct the small positional difference between field-surveyed plot geometry and cadastral/map plot geometry.

Allow:
Select parcel/layer → drag/move geometry → align with reference map → release.

Also provide precise X/Y translation where practical.

Important:
Map Pan = moves only the map viewport.
Move Geometry = moves only selected cadastral geometry.

Never move the basemap or unrelated parcels.

Original geometry must remain recoverable through Undo/Reset.

4. NON-DESTRUCTIVE GEOMETRY SHIFT

Use:
Original Geometry → Transformation/Shift → Display Geometry → Export Geometry

Store translation/rotation/scale separately where possible.

This allows:
- Undo shift
- Reset shift
- Compare original and corrected geometry
- Export corrected geometry

5. CADASTRAL ALIGNMENT

Use the existing GCP mathematics where appropriate.

Workflow:
Select source geometry → select corresponding reference point(s) → calculate shift/transformation → preview → apply.

At minimum support translation.

Where already supported by the existing GCP mathematics, retain/use:
- Similarity
- Affine
- Projective
- TPS

For normal cadastral field/map shifts, prefer the least-distorting transformation.

6. GCP CSV IMPORT

When Load GCP is selected, first display a format-selection popup.

Support:
- Auto Detect
- ID, Easting, Northing, Elevation
- ID, X, Y, Z
- ID, Latitude, Longitude, Elevation
- Custom column mapping

Show a preview of the CSV before importing.

Allow selection of:
- Point ID
- X/Easting/Longitude
- Y/Northing/Latitude
- Elevation
- Delimiter
- CRS

Only import after the user confirms the format.

Retain the existing GCP fitting, residual checking, outlier detection and transformation functionality.

7. COLLAPSIBLE CADASTRAL TOOLS

Make these sections collapsible:
- How This Works
- Cleanup
- Edit
- Ground Control Point
- Import/Export
- Settings

Keep the cadastral map area as large and uncluttered as possible.

8. UNDO/REDO

At the beginning of the editing controls place:

Undo | Redo | Remove Last | Reset Everything

Extend the existing history system rather than replacing it.

Undo/Redo must support:
- Parcel creation
- Parcel deletion
- Vertex editing
- Geometry movement
- Geometry shifting
- Cleanup
- GCP changes
- Other reversible editing operations

9. CLEANUP

Keep the existing topology/cleanup system and make Cleanup collapsible.

Retain existing capabilities such as:
- Regularise parcel geometry
- Snap shared edges
- Detect overlaps
- Geometry quality checks
- Other existing topology validation

Cleanup must work on both digitized and imported cadastral geometry.

Destructive cleanup operations must be undoable.

10. EDIT

Make Edit collapsible.

Include/retain:
- Select
- Move Geometry
- Move Vertex
- Add Vertex
- Delete Vertex
- Rotate
- Scale
- Copy
- Duplicate
- Delete
- Existing editing tools

11. IMAGE/PDF CADASTRAL DRAWING WORKSPACE

Use and extend the existing raster workspace.

Images and PDFs must work as cadastral/survey drawing underlays, not merely ordinary pictures.

Allow:
- Import/open
- Position
- Rotation
- Opacity
- Lock/unlock
- RF scale calibration
- GCP georeferencing
- Parcel digitization over the drawing

12. IMPORTANT — RF DRAWING SCALE

When a cadastral drawing contains an RF scale such as:
1:500
1:1000
1:2000
1:5000

allow the user to enter that RF value.

This is NOT ordinary image resizing.

The application must use the RF to establish the actual real-world drawing scale.

Example:
RF 1:2000 means 1 unit on the drawing represents 2000 corresponding units on the ground.

Clearly distinguish:
- RF drawing scale
- Real-world ground/map distance
- Screen zoom

Changing screen zoom must never change the actual calibrated drawing scale.

13. SCALE-BAR CALIBRATION

Also allow calibration from a known scale bar/distance:

Pick two points on drawing → enter known ground distance → calculate scale.

Store this calibration inside the project.

14. IMAGE/PDF + GCP GEOREFERENCING

After RF/scale calibration, allow GCP-based positioning:

Import Drawing → Set RF Scale → Add GCPs → Match GCP to Map Coordinates → Calculate Transform → Preview → Apply

At minimum support:
- Translation
- Scale
- Rotation

Use affine/projective transformation where appropriate and supported by the existing GCP engine.

15. PDF HANDLING

Retain the existing project's browser limitation handling for PDF pages.

If the browser cannot directly access PDF viewer pixels, provide the appropriate capture/render workflow instead of pretending direct PDF pixel access exists.

The rendered/captured PDF page must then behave as a calibrated cadastral drawing workspace.

16. DXF IMPORT

Allow DXF import through:
Import ▾ → DXF

Imported DXF geometry must:
- Automatically overlay the map
- Preserve coordinates
- Preserve DXF layers where possible
- Preserve plot/parcel information where available
- Be selectable/editable
- Be movable
- Be exportable after correction

Do not destroy absolute survey coordinates during import.

17. CSV VERTICES IMPORT

Allow:
Import ▾ → CSV Vertices

Support:
- ID, X, Y
- ID, Easting, Northing
- ID, X, Y, Z
- ID, Latitude, Longitude

Provide column mapping and CRS selection.

Create editable cadastral geometry from the vertices.

18. KMZ/KML IMPORT

Allow:
Import ▾ → KMZ/KML

Read supported KML/KMZ geometry and automatically overlay it.

Preserve where possible:
- Plot boundaries
- Plot numbers
- Names
- Attributes
- Styles

Unsupported objects should be skipped gracefully instead of crashing.

19. PROJECT JSON

Extend the existing project serialization so that a saved project can completely reconstruct the cadastral workspace.

Store:
- Project name
- CRS
- Parcels
- Plot numbers
- Attributes
- Imported layers
- Digitized layers
- GCPs
- GCP transformations
- Geometry shifts
- Image/PDF calibration
- RF scale
- Rotation
- Layer visibility
- Styles
- Relevant workspace settings

Reopen through:
Import ▾ → Project JSON

The complete project must be restored as fully editable.

20. SAVE PROJECT

Save Project is a separate main button.

It should quickly save the current complete cadastral workspace as:
ProjectName.json

If already saved, update the current project rather than creating unnecessary duplicates.

21. GOOGLE EARTH COMPATIBILITY

Do not attempt to make proprietary project JSON directly readable by Google Earth.

Use:
Export ▾ → KML/KMZ

Preserve where supported:
- Parcel boundaries
- Plot numbers
- Names
- Attributes/descriptions
- Styles
- Corrected coordinates

Workflow:
Digitizer Project JSON → Export KML/KMZ → Google Earth

22. CAPTURE VIEW

Keep/improve Capture View.

When activated:
1. Prepare the cadastral drawing/map workspace.
2. Hide/minimise the Digitizer UI where technically possible.
3. Capture the clean map/drawing view.
4. Restore the Digitizer.

Do not claim OS-level minimisation if browser security prevents it.

23. IMPORTED GEOMETRY MUST USE THE EXISTING EDITING SYSTEM

Do not create a separate editor for imported files.

Imported cadastral geometry must use the same editing system as digitized parcels so that:
- Edit
- Move
- Cleanup
- GCP
- Undo/Redo
- Area calculation
- Export

work consistently.

24. LAYER MODEL

Maintain a clear distinction between:
- Reference Map
- Imported Cadastral Geometry
- Digitized Geometry
- Image/PDF Drawing
- GCPs

Imported and digitized geometry must be independently selectable and editable.

25. EXPORT AFTER CORRECTION

If a parcel is shifted or transformed, export the final corrected geometry.

Do not silently export the original unshifted geometry.

26. DO NOT CONFUSE THESE OPERATIONS

Map Pan:
Changes viewport only.

Geometry Move:
Changes selected parcel position.

RF Scale:
Defines drawing-to-ground scale.

Screen Zoom:
Changes visual magnification only.

GCP Georeferencing:
Calculates spatial transformation between drawing/reference coordinates.

These operations must remain independent.

27. USE THE EXISTING PROJECT ARCHITECTURE

Do not unnecessarily duplicate existing systems.

Extend and preserve the current architecture, including:
- page_inject.js
- raster_workspace.js
- gcp_math.js
- history.js
- exporters.js
- crs.js
- topology.js
- site_adapters.js
- Existing tracer/viewport functionality

Preserve the current map-adapter architecture for supported mapping engines.

28. FINAL CADASTRAL WORKFLOWS

Field Geometry Correction:
Import DXF/KMZ/CSV → Automatic Overlay → Select Geometry → Move/Align → Edit/Cleanup → Export Corrected Geometry

Scanned Cadastral Drawing:
Import Image/PDF → Enter RF Scale → Calibrate → GCP → Georeference → Digitize → Save Project → Export

Project Reuse:
Save Project → JSON
Later:
Import ▾ → Project JSON → Complete Editable Project Restored

Google Earth:
Export ▾ → KML/KMZ → Open in Google Earth

29. FINAL UI PRINCIPLE

The main workspace must remain:

IMPORT ▾ | EXPORT ▾ | SAVE PROJECT

Import and Export open their respective format dropdowns.

Do not create additional permanent Import/Export buttons.

Keep advanced functionality inside the appropriate collapsible sections.

30. REGRESSION TESTING

Before finalising, run the existing test suite and add tests for the new functionality.

Verify:
- Automatic import overlay
- DXF import
- CSV vertex import
- KMZ/KML import
- Project JSON import
- Project JSON save
- Corrected geometry export
- Geometry movement

- GCP CSV format confirmation
- Image RF scale
- PDF RF scale
- Image/PDF GCP georeferencing
- Cleanup on imported geometry
- Edit on imported geometry
- Project save/reopen
- KML/KMZ Google Earth export
- Capture View

Do not delete or weaken existing tests simply to make the new implementation pass.

FINAL PRINCIPLE

This is a BhuNaksha/cadastral survey digitizer, not a generic drawing application.

Prioritise:
parcel boundaries → cadastral coordinates → plot numbers → survey accuracy → RF map calibration → GCP georeferencing → field/map alignment → topology → reliable export.

Preserve the existing CRS, GCP, topology, tracing and map-adapter architecture and add the requested functionality around it rather than replacing the existing core.
